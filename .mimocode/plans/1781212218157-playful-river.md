# Fix: nil pointer dereference in chat send

## Root Cause

`main.go:139-149` loads `system_prompts.json` via a 3-step fallback chain. Every `LoadPrompts` call discards its error with `_`. If the configured path is invalid OR the working directory at runtime differs from the project root, all three attempts fail silently and `prompts` stays `nil`.

This nil pointer is passed into `workspace.Handler.prompts`. When `HandleChatSend` calls `h.prompts.Get("chat_system")` at `handler.go:121`, it dereferences nil → panic.

## Fix

**File: `main.go` (lines 139-149)**

After the fallback chain, add a fatal guard if `prompts` is still nil:

```go
var prompts *llm.Prompts
if path := cfg.SystemPromptsPath; path != "" {
    prompts, _ = llm.LoadPrompts(path)
}
if prompts == nil {
    if _, err := os.Stat("pi_bundle/system_prompts.json"); err == nil {
        prompts, _ = llm.LoadPrompts("pi_bundle/system_prompts.json")
    } else {
        prompts, _ = llm.LoadPrompts("templates/system_prompts.json")
    }
}
if prompts == nil {
    log.Fatal("failed to load system prompts from any source")
}
```

This is a 1-line addition at line 150. Fail-fast prevents the nil pointer panic at runtime and gives a clear error message.

## Verification

1. Delete/rename `templates/system_prompts.json` → app should `log.Fatal` with clear message on startup
2. Restore the file → app starts normally, chat works
3. Set `SYSTEM_PROMPTS_PATH=/nonexistent/path` → app should `log.Fatal`
4. Set `SYSTEM_PROMPTS_PATH=` (empty) → app loads from fallback paths, works fine
