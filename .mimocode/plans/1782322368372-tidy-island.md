# Plan: Add Clear Chat Button

## Current Architecture Analysis

### Frontend (templates/chat.html)
- **Chat history**: Stored in `localStorage` as `chat_history` (JSON array of `{role, content}` objects)
- **Load**: `loadChatHistory()` renders messages from localStorage on page load
- **Save**: `saveChatHistory()` persists to localStorage after each message
- **No clear button exists** in the current UI

### Backend (internal/workspace/service.go, handler.go)
- **ChatStore**: In-memory session store (`map[string]*Session`)
- **Chat function** (line 139): Always prepends system prompt + resume to messages, then appends session history
- **ClearChat** (line 198): Deletes session from store
- **HandleChatClear** (handler.go:223): Endpoint `POST /api/chat/clear` already exists!

### System Message
- Defined in `templates/system_prompts.json` as `chat_system` (humanizer prompt)
- Loaded once at startup and passed to each `Chat()` call
- **Always prepended** to messages when making LLM calls (line 147-148)
- Clearing chat history does NOT affect system message - it's always fresh

## Key Finding

The backend `/api/chat/clear` endpoint already exists but the frontend has no button to trigger it. The system message is already designed to be always present (prepended on each LLM call), so clearing works correctly.

## Implementation Plan

### 1. Add Clear Chat Button to UI (templates/chat.html)
- Add a "Clear" button next to the existing "Prompts" button in the header bar (line 19)
- Style it consistently with the existing buttons

### 2. Add Clear Chat Handler (JavaScript)
- Add click event listener for the clear button
- On click:
  1. Call `POST /api/chat/clear` to clear server-side session
  2. Clear `localStorage.removeItem('chat_history')`
  3. Reset `chatHistory = []`
  4. Clear `chatMessages` div (remove all message elements)
  5. Show `emptyState` again
  6. Clear `pendingJobId` if any
